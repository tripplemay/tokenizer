## 3. Timeout-safe owned observation and strict inclusive caps

Embed the copied guard semantics in the new CLI; load its `?guard=1` URL **before** the unchanged old trace import. The guard obtains the exact admitted PowerShell `ChildProcess` from the original async spawn and attaches additive Buffer listeners **before returning that handle** to trace/worker. Match case basename, worker path/payload, exact command/argv/script, budget and positive PID. Do not accept milestones from Node/Git/taskkill, a historical PID, another handle or only matching text. Do not `read`, `pipe`, `setEncoding`, replace/remove listeners, destroy streams, alter worker protocol/timers/results or write anything to worker stdout.

Parse LF/CRLF-terminated exact ASCII tokens only, split anywhere across Buffer chunks. No trim, substring, BOM, whitespace variants, blank lines, unknown text, duplicate/reordered/wrong-variant tokens or unterminated fragment. Bound the pending line to the longest admitted token plus CRLF (29 bytes INITIAL). Count stdout and stderr together; any stderr is invalid. Count rejected bytes as well. Maintain a saturating combined count at 16385 (the overflow sentinel), independently capped per-stream counts at 16384, and retain no raw fallback. Stop accepting markers after invalidity/overflow. Preserve the unchanged worker's own cap and termination behavior.

Each complete accepted line is synchronously rebuilt and persisted as `native-fixed-stage` **inside the worker-process listener**, before timeout result construction can discard native stdout. Root polling while blocked in `runBoundedSubprocess` cannot substitute for this. `ordinal` is zero-based; arrival elapsed is observer monotonic time since owned native spawn, not cmdlet execution time. End events track each stream's actual `end`; `close`/destroy alone is not EOF. Emit exactly one `native-fixed-stream-end` at child close (or safe finalization), including both EOF flags. Missing end event itself is unknown. Strict event keys and safe types are in JSON.

The new stream state is invalid on parser violation/nonzero stderr/cap overflow; otherwise unknown on stream error or missing EOF; otherwise complete-sequence or complete-prefix. `eofObserved` equals both EOF flags. An incomplete clean sequence is a prefix, not success. First parser violation supplies its fixed reason, except overflow takes precedence. No raw text/error message/path/module object is persisted.

**Strict append mechanism, not a pre-append race:** use one atomic `mkdirSync` lock per bounded file, with saved pre-trace filesystem primitives. Exact lock paths are JSON-bound. Under that lock, verify owned regular-file identity/no symlink, read current size, serialize the candidate to bytes, and append only if `size+candidateBytes <= cap`; exact cap is allowed. Counter parsing, limit checks and admission append are one transaction under its run-root lock. Contention, missing/corrupt identity, partial write, acquisition/release failure or overflow immediately fails evidence/health closed: no spin, wait, retry or stale-lock takeover. All permitted writers must pass this gate. Install the exact-path `fs.appendFileSync` wrapper before old trace captures it, then sync builtin exports, so old trace appends also use the gate without editing its source. No other filesystem target is wrapped; no raw log is uploaded. Lock operations using saved primitives are an explicit observation-I/O delta, not hidden parity. Existing strict read/rebuild/overflow suppression remains mandatory after writing. Do not claim that the old pre-append check itself provides a hard cap.

Preserve live-owned-handle tree termination, watchdogs, observed-PID sampling, separate guard/trace health and retained-root rules from the frozen CLI. Never signal historical evidence PIDs or scan by process name. Neither a child close nor sampled dead PID proves entire-tree absence. EOF, guard/trace health, ownership/provenance and cleanup must each be trustworthy; none overrides another. Unknown retains roots under the original policy and blocks progression.

## 4. Locked selection and root protocols

Apply the JSON table once, sequentially. `trustworthy` means strict root/probe/event identity and sequence, both EOFs, no stderr/overflow/abort, all expected guard/trace health complete, valid counter and known cleanup/provenance, including the closed native tuple/source relations below. Launch/output/supervision/unknown are never clean refusal.

### B001: native return/throw closure (required before selection)

`native.metadataSource` is `api-return`, `api-throw`, `not-started` or `unknown`. It identifies an actually observed `runBoundedSubprocess` return/catch, not a conclusion inferred from trace or marker text. Native `status/signal` are **API return fields only**, never values copied from a Node worker's spawn-sync result or filled from native close facts on a throw path.

| Path/outcome | Required native tuple and source |
|---|---|
| Normal return / completed | `metadataSource=api-return,workerKind=ok,status=0,signal=null,errorName=null,errorCode=null`; exact full marker sequence. |
| Normal return / clean refused | `metadataSource=api-return,workerKind=ok`, safe **nonzero** returned status, `signal=null,errorName=null,errorCode=null`; permitted clean prefix. |
| API throw / timeout | `metadataSource=api-throw,workerKind=timeout,status=null,signal=null,errorName=BoundedSubprocessTimeoutError,errorCode=null`. No invented status 0, EIO or inferred signal. |
| API throw / output, launch or supervision | `metadataSource=api-throw,status=null,signal=null`; respective actual API class. Output/supervision code is null; launch code is only the safe mapping of the actual `BoundedSubprocessLaunchError.code` (absent means null). Never clean refusal/progression. |
| Not started / unknown source | No unavailable return/error fields: status/signal/errorName/errorCode null. Not-started also has workerKind/elapsedMs null. Missing or unsupported actual error source is unknown, not a diagnostic error renamed as a product API error. |

For normal returns, require one uniquely admitted native childPid under the same owning worker PID, fixed case/root/script and spawn admission. Reconcile the returned native status/signal against **both** original guard and old-trace `child-exit` and `child-close` facts for that handle; all four facts must be present, unique and mutually equal to the returned tuple. `spawn-sync` status/signal refers to the Node worker and cannot satisfy this equality check. Native close/exit facts on a throw path are independent observations only; reconcile their ownership and mutual consistency, but do not copy them into unavailable return fields or guess what the API would have returned.

Missing/duplicate/contradictory admission, API-source/error/worker relation or native exit/close tuple makes the observation unknown and blocks T1/T2 progression. Reject the conflicting raw protocol; rebuild only a safe unknown case, retaining independently observed facts/unknown flags rather than laundering a tuple into clean refusal. No worker partial-output change, extra native/host query or added surface is required or permitted. The existing EOF/health/cleanup/provenance requirements remain independent and unchanged.

* **T1 success stops immediately**; T2/T3 are skipped. This is a conservative INITIAL narrowing approved by Coordinator, not a claim about an executed run. Clean T1 timeout/refusal with empty prefix admits T2; anything else stops unknown.

Unknown/missing post-crash records must not be fabricated as skips or zero admissions: nullable count/start fields and `decision=unknown` preserve uncertainty. Cases always appear once in T0-T3 order. `native_completed`, `prefix_protocol_valid`, `diagnostic_observation_complete` and release flags stay separate.
