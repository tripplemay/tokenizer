# 升级计划决策补充（2026-10-08）

本文件只记录原计划形成后的用户裁决和验收边界；原始 `README.md`、`plan.json`、`validation.json` 保留其 2026-10-07 规划快照语义。实施/验证进度另见 `docs/test-reports/upgrade-20261007/integration-status.md`。

| 议题 | 用户裁决 | 对工作包和验收的约束 |
| --- | --- | --- |
| B02 构建依赖风险 | 继续修复依赖后发布，不接受未修复残留风险 | 修复真实安装/执行代码并独立复验；扫描器仅按包名/版本继续告警时，要以精确 SHA、安装图、补丁哈希、负控及 CI 证据界定误报，不能把风险接受写成修复。任何 vendor/lock/override 变化都使原判定失效。 |
| B03 `local-only` 切回 `sync` | 切换后自动上传本机已排队积压 | 默认不删除积压、不静默丢弃；切换前呈现数量与影响，切换后按现有有界重试/ACK 语义上传。历史积压仍须符合当时已准入的隐私边界。 |
| B03 include/exclude 规则修改 | 仅对之后的采集生效；过去被排除事件不自动补采 | 不因配置改变隐式扫描旧文件或移动历史 cursor。旧排除数据只有通过单独、显式、有界的 replay 才能进入队列；replay 要有 dry-run、范围/数量/字节/时间上限、确认摘要与去重/取消。 |
| F005 真实生产浏览器验收 | 用户准备已登录的测试标签页，不提供密码 | 收到可定位的登录标签页后执行真实旅程；合成认证浏览器 CI 不能替代 F005 签收，也不得在缺少标签页时标记通过。 |
| 最终发布责任 | 本主会话兼任编排者发布 | 子 agent/外部 CLI 不推送任何分支；编排者回流、核验精确 SHA 与主分支发布条件后才执行 push-main/生产验收。`pending_gate.decision` 仍只由人闸门决定。 |

这些裁决不把 M0-M7/B00-B29 自动改为已完成。特别是 B03 replay 与 UI backlog 预览、B06 客户端逐行 ACK、B04 原生平台矩阵、B05 main-only provenance/真实恢复和 F005 登录态生产验收均有各自证据门。
